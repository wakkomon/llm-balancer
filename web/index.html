Server

Basis-URL des LLM-Servers ohne /v1 – der Pfad der Anfrage wird angehängt.
Ollama-Server bekommen zusätzlich Anfragen an die Ollama-API (/api/chat …) und lassen sich auf der Seite Modelle verwalten.
Kleinere Priorität wird bevorzugt, wenn mehrere Server frei sind.
Modellname oder Muster mit *; „–“ = unbekannt. Ollama-Modelle werden automatisch erkannt, Einträge hier haben Vorrang.
Wird statt des angefragten Modells gesendet, wenn der Server dieses nicht exakt kennt – also bei Treffern über * im Filter oder wenn er die Anfrage als Teil seiner Gruppe bekommt. Exakt bekannte Modelle gehen unverändert durch.
Bestimmt, welcher Server einer Gruppe eine Anfrage bekommt. Ein exakt bekanntes Modell (vom Server gemeldet oder hier ohne * eingetragen) hat Vorrang vor einem Treffer über *. Leer + Haken = nur die gemeldeten Modelle.
Ausgehende Preise, z. B. Strom/Hardware oder ein bezahlter Anbieter – erscheinen als „Kosten Server“ in der Statistik.
Erreichen die Kosten des Servers den Deckel, bekommt er keine Anfragen mehr (Fallback greift) – bis zum nächsten Tag/Monat.
Wird als „Authorization: Bearer …“ an diesen Server geschickt.

Router

Clients fragen dieses Modell an, z. B. "model": "auto"; es erscheint in /v1/models.
Leer: bei übernommenen echten Modellen bleibt das angefragte.
Damit werden auch Anfragen mit echtem Modellnamen umgeleitet. Leer = nur das virtuelle Modell.
Mehrere Modelle (mit Komma) gelten als gleichwertig: die Anfrage geht an den ersten freien Server, der eins davon hat – bei mehreren freien an das weiter vorne genannte; sind alle belegt, wartet sie auf den, der zuerst frei wird. Der Modellname wird passend zum Server gesetzt.
„Fähigkeiten beachten“: kann das gewählte Modell nachweislich etwas nicht, was die Anfrage braucht (laut Server-Einstellungen oder Ollama), nimmt der Router ein Modell, das es kann.

Regeln – von oben nach unten, die erste passende gewinnt; leere Felder = egal

Wenn keine Regel passt

Modelle pro Stufe – mehrere mit Komma sind gleichwertig. Leere Stufe = nächsthöhere.
Score aus Länge, Code, Reasoning-Markern, Fachbegriffen, einfachen Fragen, mehrstufigen Aufträgen und Fragezeichen (Gewichte wie LiteLLM). Zwei oder mehr Reasoning-Marker („Schritt für Schritt“, „analysiere“, „vergleiche“ …) → REASONING.
Routen für Arch-Router: kurzer Name, eine Beschreibung, wofür die Route da ist (auf Englisch funktioniert am besten), und das Modell. Antwortet das Modell „other“, gilt das Standardmodell.
Der Klassifizierer läuft am Slot-System vorbei direkt auf dem Server, damit er nicht auf das große Modell wartet. Bei Ollama bleibt das Modell 30 min geladen – dafür sollte OLLAMA_MAX_LOADED_MODELS ≥ 2 sein. Mit Session-Bindung wird nur die erste Anfrage einer Unterhaltung klassifiziert.

Gruppe

Anfragen, die ein Server dieser Gruppe bearbeitet, bekommen diesen Modellnamen – die Zuordnung zur Gruppe erfolgt weiter über den angefragten Namen (mit „*“ in den Modellen nimmt die Gruppe jedes Modell an).
Wartet eine Anfrage länger als angegeben, darf auch ein Server der Fallback-Gruppe sie übernehmen. Sind alle Server dieser Gruppe down, sofort. Mit „Modell dort“ wird der Modellname für den Fallback ersetzt.
Ein Server gehört zu höchstens einer Gruppe; wählst du ihn hier, verlässt er seine bisherige.

Preis

Erreicht der Token den Deckel, werden seine Anfragen mit HTTP 429 abgelehnt – bis zum nächsten Tag/Monat oder bis der Deckel erhöht wird.
